# omp-superagent 0.1.9

- **Change the model for a Discord work thread.** Open `/model` and select HEAD or the lane bound to that thread. A verified lane quota failure pauses that lane's queue and notifies the original conversation without starting a HEAD turn or replaying the failed request. OMP's temporary retry fallback does not overwrite the lane's configured choice (#50).
- **A tool-free HEAD failure no longer stalls the queue.** When the exact native journal proves the request failed before any tool started, HEAD can close it without replay and move on. Quota failures still require recovery evidence. For uncertain effects, the notice identifies the exact `/resolve <input-id>` to use after checking what happened (#54).
- **Discord now uses `/usage-reset`.** `/usage` is read-only and takes no options. `/usage-reset` opens the account picker; spending a ticket still requires confirmation. Telegram and Slack command syntax is unchanged. Reopened lane work sends progress and the final answer to the original work thread while keeping the original approval route (#52, #53).
- **Native Gateway handles more I/O.** Avatar updates, messenger command registration, SSH relay, and attachment staging move to Rust. Inbound attachments are staged in a private directory and checked against Gateway receipts before use. The npm package still includes native binaries for macOS and Linux on arm64 and x64.
- **Current omp-superkit layouts install cleanly.** Managed setup checks canonical `super` and `super-*` skills and their command pointers while preserving valid legacy revisions.

## Install or upgrade

```sh
bun add --global --trust omp-superagent@0.1.9
omp-sa --help
```

Alternatively, use `npm install --global omp-superagent@0.1.9` with Bun 1.4.4 or later on `PATH`. OMP is installed separately; CI uses stock OMP 19.1.1. Installing does not restart a running Gateway. Before re-registering Discord commands, update both Gateway and HEAD, then check that Discord `/help` lists `/usage-reset`.
